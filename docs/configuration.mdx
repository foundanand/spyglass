---

The collector reads exactly one JSON file, passed with `--config`:

```bash
spyglassd --config spyglass.config.json
```

Configure it once and you never touch it again. Here is every key:

```json title="spyglass.config.json"
{
  "listen": ":7474",
  "dataDir": "./data",
  "apps": {
    "inventory": {
      "key": "sg_live_pick_a_long_random_string",
      "origins": ["http://localhost:3000", "https://inventory.internal.acme.dev"]
    }
  },
  "retention": { "replays_days": 21, "events_days": 0 },
  "auth": { "dashboard_password": "env:SPYGLASS_PASS" }
}
```

---

## `listen`

The address the HTTP server binds to. Default `:7474`. Use `:PORT` for all
interfaces or `127.0.0.1:PORT` to bind locally only.

## `dataDir`

Directory for the SQLite database (`spyglass.db`) and replay blobs
(`replays/`). Default `./data`. Created on boot if it doesn't exist. **This is the
only state spyglass keeps** — back it up by copying the directory.

```
data/
  spyglass.db          # events + sessions (SQLite, WAL mode)
  replays/
    <session_id>/
      meta.json
      000001.json.gz   # gzipped rrweb chunks
```

## `apps`

A map of app slug → settings. At least one app is **required**; the collector
refuses to start otherwise. The SDK's `app` and `key` must match an entry here.

| Field        | Required | Purpose                                                                  |
| ------------ | -------- | ------------------------------------------------------------------------ |
| `key`        | yes      | Key the SDK presents on every ingest request. Any long random string.    |
| `server_key` | no       | Separate secret for non-browser callers. Enables server-side ingest.     |
| `origins`    | no       | Allowed browser origins (CORS) for this app. Add your dev and prod URLs. |

Run several apps off one collector by adding more entries — each with its own key.

<Callout type="info">
  The app `key` authenticates **ingest** (`/v1/events`, `/v1/replay`). It is separate from the
  dashboard password, which gates the *reading* side.
</Callout>

### `server_key` — reporting from a worker or cron job

Optional and absent by default, in which case only browsers can report.

```json
"apps": { "inventory": { "key": "sg_live_…", "server_key": "env:SG_SERVER_KEY" } }
```

The browser `key` ships to the client and is public by design, which is why it is
paired with `origins`. A `server_key` is a real secret — never sent to a client —
and so it is allowed to skip the origin check, because a server has no meaningful
`Origin` to present. **The collector refuses to start if the two are equal**,
since that would let every browser skip the check and make the allowlist
decorative.

See the [server-side snippet](/docs/api#reporting-from-a-server) for the request
shape. Pass the browser's `session_id` where you have one, so the server event
lands on that session's timeline rather than becoming a parallel firehose.

## `retention`

How long data is kept. A value of `0` means **keep forever**.

| Field          | Default | Meaning                                                                |
| -------------- | ------- | ---------------------------------------------------------------------- |
| `replays_days` | `21`    | Delete replay directories older than N days.                           |
| `events_days`  | `0`     | Delete events older than N days. `0` = keep forever (events are tiny). |

A retention sweep runs once on boot and then every 24 hours, in-process. Replays
are bulky (MBs per active hour) so they expire by default; events are rows worth
bytes, so they're kept indefinitely unless you set `events_days`.

## `auth`

| Field                | Purpose                                                |
| -------------------- | ------------------------------------------------------ |
| `dashboard_password` | Password gating the dashboard and all query endpoints. |

When set, the dashboard and every read endpoint require [HTTP Basic auth](/docs/deployment#authentication)
(any username, this password). When **empty or omitted**, the dashboard is open —
fine for localhost, not for anything reachable by others.

## `webhooks`

The **only** setting that lets the collector originate a network connection.
Omit it and none is possible — see [Air-gapped deployment](/docs/deployment).

| Field           | Purpose                                                             |
| --------------- | ------------------------------------------------------------------- |
| `on_bug_report` | POSTed when a user files a bug report.                              |
| `on_new_error`  | POSTed the first time an error signature appears in a 15m window.   |
| `dashboard_url` | Public base URL of this collector, used to build the incident link. |

```json
"webhooks": {
  "on_bug_report": "env:SG_WEBHOOK",
  "on_new_error": "env:SG_WEBHOOK",
  "dashboard_url": "https://spyglass.internal"
}
```

The body is small JSON with a Slack-compatible `text` field alongside structured
`kind`, `app`, `user`, `name` and `incident_url` — Slack-shaped by default
because that is the common case, but a plain webhook so anything can receive it.

Delivery is fire-and-forget with a 5-second timeout and no retry queue: a slow
or dead receiver logs a line and never delays or fails ingest. Repeats of the
same signature within 15 minutes are collapsed, so an error spiking across every
session is one message rather than hundreds.

<Callout type="warn">
  This is the project's only egress. Point it at a receiver inside your own network and the air-gap
  guarantee holds; point it at a public host and you are choosing to send bug report text outside
  it. The collector logs `webhooks: enabled` at startup so this is visible from the logs alone.
</Callout>

## Env-var resolution

Any string value of `"env:NAME"` is replaced at load time with the environment
variable `NAME`. The collector **fails to start** if the variable is unset, so a
missing secret is a loud error, not a silent open door.

```json
"auth": { "dashboard_password": "env:SPYGLASS_PASS" },
"webhooks": { "on_bug_report": "env:SG_WEBHOOK" }
```

```bash
SPYGLASS_PASS='a-strong-password' spyglassd --config spyglass.config.json
```

Keep real secrets out of the file this way and commit the config safely.

## Defaults at a glance

| Key                       | Default            |
| ------------------------- | ------------------ |
| `listen`                  | `:7474`            |
| `dataDir`                 | `./data`           |
| `retention.replays_days`  | `21`               |
| `retention.events_days`   | `0` (keep forever) |
| `auth.dashboard_password` | empty (no auth)    |
| `webhooks`                | absent (no egress) |

A copyable starting point lives at `spyglass.config.example.json` in the repo.
